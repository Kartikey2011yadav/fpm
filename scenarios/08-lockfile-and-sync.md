# Scenario 8: Lockfile & Reproducible Environments

## What This Proves

fpm generates deterministic lockfiles and can sync any environment to match them
exactly. This guarantees that what works on your machine works in CI, staging,
and production — down to the exact byte.

---

## Setup

```bash
rm -rf /tmp/fpm-demo-lock && mkdir -p /tmp/fpm-demo-lock && cd /tmp/fpm-demo-lock
fpm init .
```

> No activation needed — fpm detects the project by directory.

---

## Step 1: Install Packages

```bash
fpm install requests flask pandas
```

**Expected:** All packages + transitive dependencies installed into `.venv`.

---

## Step 2: Generate Lockfile

```bash
fpm lock
```

**Expected:** Creates `fpm.lock` in the project root.

```bash
cat fpm.lock
```

**Expected Output (structure):**

```toml
# fpm.lock — DO NOT EDIT MANUALLY
# Generated by fpm on 2026-06-10T14:30:00Z

[metadata]
python = "3.12.13"
platform = "darwin_arm64"
generated = "2026-06-10T14:30:00Z"

[[package]]
name = "requests"
version = "2.34.2"
hash = "sha256:abcdef1234567890..."
dependencies = ["urllib3>=2.0", "charset-normalizer>=3.0", "idna>=3.0", "certifi>=2023"]

[[package]]
name = "flask"
version = "3.1.3"
hash = "sha256:1234567890abcdef..."
dependencies = ["werkzeug>=3.0", "jinja2>=3.1", "click>=8.1", "itsdangerous>=2.1", "blinker>=1.7"]

# ... all transitive dependencies with exact versions and hashes
```

Key properties:

- **Exact versions** — no ranges, no ambiguity
- **Hashes** — verify integrity (detect tampering/corruption)
- **Platform info** — know what generated it
- **Full dependency closure** — every transitive dep included

## Step 3: Destroy and Recreate Environment

```bash
# Simulate setting up on a new machine / in CI
rm -rf .venv

# Create fresh venv + sync from lockfile
fpm venv
fpm sync
```

**Expected Output:**

```
Syncing from fpm.lock...
  Installing 15 packages...
  ✓ requests 2.34.2
  ✓ flask 3.1.3
  ✓ pandas 2.2.0
  ✓ urllib3 2.7.0
  ✓ werkzeug 3.1.8
  ...
All 15 packages synced.
```

---

## Step 4: Verify Exact Match

```bash
fpm list
```

**Expected:** Exact same versions as before the destroy/recreate. Not
"compatible" versions — the EXACT same versions.

```bash
fpm run python -c "import requests; print(requests.__version__)"
fpm run python -c "import flask; print(flask.__version__)"
```

**Expected:** Same versions as the lockfile specifies.

---

## Step 5: Lockfile Detects Drift

```bash
# Install something not in the lockfile
fpm install black

# Check if environment matches lockfile
fpm sync --check
```

**Expected:**

```
Environment does not match fpm.lock:
  + black 24.1.0 (not in lockfile)

Run `fpm lock` to update, or `fpm sync` to restore.
```

---

## Step 6: Update Lockfile After Changes

```bash
fpm lock
```

**Expected:** `fpm.lock` updated to include black.

---

## CI/CD Workflow Example

```bash
# In CI (e.g., GitHub Actions):
git clone <repo>
cd <repo>

# fpm detects project by directory — no activation needed
fpm venv
fpm sync

# If sync fails (e.g., hash mismatch), CI fails loudly
# No silent version drift possible

fpm run pytest
```

## Comparison: Lockfile vs Immutable Pins vs Snapshots

| Feature         | fpm.lock             | [immutable] in fpm.toml | Snapshots               |
| --------------- | -------------------- | ----------------------- | ----------------------- |
| Scope           | All project packages | Selected packages       | Entire environment      |
| Purpose         | Reproducibility      | Safety                  | Point-in-time recovery  |
| Captures config | No (packages only)   | N/A (IS the config)     | Yes (fpm.toml included) |
| Cross-manager   | fpm packages only    | fpm packages only       | ALL managers            |
| Enforcement     | At sync time         | At install time         | At restore time         |
| Can be updated  | Yes (`fpm lock`)     | Manual edit only        | New snapshot            |

Use all three together:

- `fpm.lock` ensures reproducibility across environments
- `[immutable]` prevents accidental changes to critical packages
- `fpm snapshot` gives you instant rollback for experiments

## Key Takeaway

> `fpm lock` + `fpm sync` gives you Docker-like reproducibility without Docker.
> Every environment synced from the same lockfile has the exact same packages,
> versions, and integrity guarantees. "Works on my machine" becomes "works
> everywhere." And if you need to recover from a disaster, snapshots capture
> everything that the lockfile doesn't (config, external packages).
